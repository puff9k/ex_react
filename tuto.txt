1. Les deux briques : React et Next

React sert à fabriquer l'interface avec des composants. Un composant est une fonction qui renvoie du pseudo-HTML (le JSX) :

export default function Footer() {
  return <footer>© 2026 Ex React</footer>;
}

Un composant peut en utiliser un autre comme une balise HTML : <Footer />. Tout le site est un emboîtement de composants.

Next.js est un framework construit autour de React. Il ajoute ce que React ne fait pas seul :
- le routing, c'est-à-dire quelle URL affiche quel composant ;
- le rendu côté serveur : le HTML est fabriqué sur le serveur avant d'être envoyé au navigateur ;
- l'accès au serveur, donc à la base de données, directement depuis les composants ;
- le build, le serveur de dev, etc.

Prisma fait le lien entre le code et la base de données. Au lieu d'écrire du SQL, on écrit prisma.message.findMany().

3. Le layout : le cadre commun

src/app/layout.tsx enveloppe toutes les pages :

<html lang="fr">
  <body>
    <Header />
    <main>{children}</main>   ← la pa placer ici
    <Footer />
  </body>
</html>

children est un nom spécial en React : il désigne « ce qu'on met à l'intérieur ». Sur /contact, Next
prend contact/page.tsx et l'insère à ader et le footer ne sont écritsqu'une fois, dans le layout.

Le layout importe aussi globals.css, qui s'applique donc à tout le site.

4. Le style : CSS global et CSS Modules

Il y a deux sortes de CSS :

- globals.css : les variables (--color-primary, etc.), le reset et la typo. Ces règles s'appliquent
  partout.
- *.module.css (CSS Modules) : du CSS normal, mais limité au composant qui l'importe.

import styles from "./Header.module.css";
<header className={styles.header}>

Au build, Next renomme .header en queer__x7f2a. Deux composants peuventdonc avoir chacun une classe .title sans conflit. Chaque composant a son fichier CSS juste à côté de
lui.

5. Server Components et Client Compon

C'est le concept clé de Next moderne. s'exécute sur le serveur. Il produitdu HTML et son code n'est jamais envoyé au navigateur. Un composant serveur peut donc lire la base de
données, mais il ne peut pas réagir a

Quand un composant a besoin d'interact, ou savoir sur quelle URL on setrouve), on écrit "use client" en première ligne. Son code est alors aussi envoyé au navigateur.

8. Trois scénarios de bout en bout

A. J'ouvre /messages

1. Le navigateur demande /messages au
2. Next trouve app/messages/page.tsx et l'insère dans layout.tsx.
3. Pendant que la page attend ses dontenu de loading.tsx (le spinner).
4. La page exécute await getMessages(), puis messages.ts interroge la base via Prisma.
5. La page génère la liste en HTML, e spinner.
6. Le navigateur affiche la page. Seul le code de NavLink y est téléchargé, puisque c'est le seul
   composant client de la page.

Le composant va chercher ses données  pas d'appel d'API depuis lenavigateur.

B. J'envoie le formulaire de contact

1. ContactForm.tsx affiche le formulaire. Son attribut action={formAction} est relié à la fonction
   sendMessage de actions.ts.
2. Au clic sur « Envoyer », le navigateur envoie les champs au serveur. Next s'en charge
   automatiquement, sans route d'API des Server Actions, qu'on signale par"use server" en haut du fichier.
3. Pendant l'envoi, isPending vaut trvoi… » et se désactive.
4. Sur le serveur, sendMessage :
   - lit les champs (formData.get("na
   - les vérifie avec validateMessage(). En cas d'erreur, elle renvoie { errors: {...} } et le
     formulaire affiche les messages
   - sinon, elle appelle createMessage(), qui passe par Prisma et insère le message en base ;
   - appelle revalidatePath("/messagersion en cache de /messages estpérimée » ;
   - renvoie { success: true }.
5. useActionState reçoit ce résultat et redessine le composant, qui affiche « Merci ! ».

C. J'ouvre /messages/42

1. Next associe l'URL à messages/[id]/page.tsx, avec params.id = "42".
2. La page appelle getMessageById(42)
3. Si le message n'existe pas, notFound() interrompt le rendu et Next affiche not-found.tsx.
4. Si la base plante, l'erreur remontose un bouton « Réessayer ».
5. generateMetadata définit le titre de l'onglet, par exemple « Message de Alice | Ex React ».

9. Et l'API, à quoi sert-elle ?

Le site lui-même n'utilise pas api/messages/. Les pages lisent la base directement et le formulaire
passe par la Server Action.

Les routes route.ts servent aux clienile, un script, un autre site. Le nomde chaque fonction exportée correspond à une méthode HTTP :

export async function GET()  { … }   // GET  /api/messages
export async function POST() { … }

Elles réutilisent les mêmes fonctionss. Les règles de validation ne sontdonc écrites qu'une fois.
